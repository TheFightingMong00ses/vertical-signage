# Vertical Signage

A browser-based vertical digital display designed for a door-mounted projector. Renders a live column of cards — weather, clock, announcements, a 7-day calendar, and a rotating ACM RSS feed with per-article QR codes — from a single JSON config file. No build step or framework required.

---

## Project Structure

```
Vertical-Signage/
├── config/
│   └── config.json        # Runtime configuration (widgets, display settings)
├── src/
│   ├── index.html         # Entry point — single <script type="module"> loads app.js
│   ├── style.css          # All styling, card themes, animations
│   ├── app.js             # Boot loader — reads config, initialises all widgets
│   ├── clock.js           # Clock widget
│   ├── weather.js         # Weather widget (Open-Meteo API)
│   ├── rss.js             # RSS feed card (multi-slot, QR codes)
│   └── calendar.js        # Google Calendar week view (unused — logic merged into app.js)
└── test/
    └── weather.test.js    # Jest unit tests for weather helpers
```

## How It Works

`app.js` fetches `config/config.json` on load, applies display settings, and initialises each widget in order. Cards are appended to `#signage-column` in the sequence: weather (prepended to top) → clock → config-driven announcement cards → calendar → RSS (always last).

All modules are plain ES modules loaded via `<script type="module">`. There is no bundler, no npm run step, and no framework. The page must be served over HTTP (not opened as a `file://` URL) for fetch and CORS to work correctly.

## Configuration (`config/config.json`)

```json
{
  "widgets": [
    { "type": "weather", "provider": "open-meteo", "lat": 39.74, "lon": -104.9847 },
    { "type": "clock", "size": 400, "theme": "light", "timezone": "America/Denver" },
    { "type": "rss" },
    { "type": "calendar" }
  ],
  "displaySettings": {
    "refreshMinutes": 10,
    "fontScale": 1
  },
  "items": [
    {
      "section": "Announcements",
      "title": "Example card title",
      "body": "Body text shown below the heading.",
      "tags": ["tag1", "tag2"]
    }
  ]
}
```

`items` is an array of static announcement cards rendered between the clock and the calendar. Each card supports `section` (label), `title`, `body`, and an optional `tags` array rendered as chips.

`displaySettings.fontScale` sets the `--vs-font-scale` CSS custom property; `refreshMinutes` controls how often the weather card refreshes.

## Widgets

### Weather (`weather.js`)

Fetches current conditions from [Open-Meteo](https://open-meteo.com/) using the lat/lon from config. Displays temperature, feels-like, wind speed and direction, and a weather emoji mapped from WMO weather codes. Prepends its card to the top of the column on init, then updates in place on each refresh cycle.

No API key required. Temperatures in °F, wind in mph.

**Exported functions:** `initWeather(lat, lon)`, `refreshWeather(lat, lon)`, `buildWeatherAPIUrl(lat, lon)`, `formatWeatherData(apiData)`

### Clock (`clock.js`)

Renders a live clock (hours, minutes, seconds) and full date string, updating every second via `setInterval`. Timezone and theme are set from config. Theme is applied as a CSS class (`vs-clock-theme-light` / `vs-clock-theme-dark`).

**Exported function:** `initClock(clockConfig)`

### Calendar (`app.js`)

Displays a 7-day week view pulled from a Google Calendar. All 7 days are always rendered — days with no events show as empty columns. The calendar refreshes every 5 minutes.

The Google Calendar API key and calendar ID are hardcoded in `app.js`. To point the display at a different calendar, update these two constants at the top of the file:

```javascript
const API_KEY = '...';
const CALENDAR_ID = '...';
```

### RSS Feed (`rss.js`)

The most complex widget. Displays 4 simultaneous feed slots stacked inside a single card, each independently cycling through articles from a pool of 12 ACM topic feeds.

**Feed cycling:** Each slot starts at a different offset in the feed list. When a slot exhausts all articles in its current feed, it advances to the next feed not already displayed in any other slot, ensuring no source repeats within a full cycle. If a feed fails to load, the slot skips it (with a "Trying next…" message), again avoiding sources already in use.

**Per-slot behaviour:** Each slot fetches its feed via `corsproxy.io`, parses the RSS XML natively in the browser (`DOMParser`), and rotates through articles on an 8-second interval with a smooth fade and height animation between articles. A progress bar and article counter are shown below each slot.

**QR codes:** Each article displays a QR code generated by [api.qrserver.com](https://api.qrserver.com) pointing at the article URL. The QR image is hidden by default and shown only once it loads successfully; it is hidden again if the request fails (e.g. on the "Trying next…" error card). QR codes fade in and out in sync with the article text.

**To change the feeds:** Edit the `FEEDS` array at the top of `rss.js`. To change the number of simultaneous slots, update `NUM_SLOTS`. To change the rotation speed, update `ROTATE_INTERVAL_MS`.

**External dependency:** `corsproxy.io` is used to proxy RSS requests around browser CORS restrictions. If the display machine cannot reach `corsproxy.io`, all feeds will fail. The QR service (`api.qrserver.com`) also requires outbound internet access.

## Running Locally

The page must be served over HTTP. The simplest way:

```bash
# Python 3
python3 -m http.server 8080
# then open http://localhost:8080/src/
```

Or use any static file server (Live Server in VS Code, `npx serve`, nginx, etc.).

## Tests

Unit tests cover the weather module's URL builder and data formatter.

```bash
npm install
npx jest
```

Tests are in `test/weather.test.js` and use Jest with ES module support.

## External Services

| Service | Purpose | Key required |
|---|---|---|
| Open-Meteo | Weather data | No |
| Google Calendar API | Week view events | Yes (hardcoded in `app.js`) |
| corsproxy.io | RSS CORS proxy | No |
| api.qrserver.com | QR code image generation | No |

All four services require outbound internet access from the display machine.
